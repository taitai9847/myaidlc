# myaidlc default rules

The framework's defaults. Do not edit this file in a project: put project rules in `docs/myaidlc/memory/project.md`, and rules for one phase in `docs/myaidlc/memory/phases/<phase>.md`. Rules are read in this order, and a later file wins where two disagree:

1. this file
2. `AGENTS.md`
3. `docs/myaidlc/memory/project.md`
4. `docs/myaidlc/memory/phases/<phase>.md`

## Output
- Every document the workflow produces (`.md`, `.html`, `.txt`) goes under `docs/`. The step's outputs go to the paths the engine gives. Product files the code itself needs (a README in a package, `requirements.txt`, an HTML template) stay where the code needs them.
- Each output starts from its template. A project template in `docs/myaidlc/memory/templates/` replaces the default one.

## Existing code
- myaidlc works on an existing project. Follow its structure, naming, error handling and tooling, as recorded in `codemap.md` and `AGENTS.md`.
- Read code only around the area the work touches, through Explore (`model: "haiku"`, thoroughness medium), as described in `protocol/stage-protocol.md`.

## The person decides
- Ask only what is the person's to decide, with options, what each means for them, and a recommendation. Never ask again what they have already answered.
- Never refuse an explicit request to approve, change, skip, jump, stop, or switch off the guard or a review. Carry it out through the engine, which records it.

## Quality
- Implementation follows `.claude/docs/dev-guideline.md`.
- Every phase that produces a design or code is reviewed before the person's last approval in that phase, and every change of code is reviewed before its checkpoint (`protocol/review.md`). Every P0 and P1 finding is applied, unless the person decides otherwise.
